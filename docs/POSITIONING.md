# 定位文档 · 允许你不读完（知识点空间 v2）

> 这份文档是产品的规范文件，不是路线图。以后任何新功能，先问它违反不违反第五、八节；违反就不做。

## 〇、一句话

- **对外（可复述）**：一个允许你不读完的读书工具。
- **对内（真内核）**：把目标翻译成「读哪些节、每个知识点到哪一档」，并只记录知识点是否真的到了那一档。
- **判断标准**：去掉 AI 之后，它还剩下什么？剩下的是边界与知识点账本；剩下的是替你总结、替你读，那两样不成立。

## 一、服务谁

**服务**：为某个具体交付物啃大部头的人——考试、论文、项目、要讲给别人听。已经在用 AI 出结果、但无法确认自己独立性的人。读 PDF 论文与教材、在电脑上读、能接受本地文件的技术型读者。

**不服务**：想被「喂」总结的人（去 NotebookLM）；想追读完数量与打卡的人；需要移动端、云同步、多人协作的人（本轮明确不支持）。

三条来自真实使用的验证（不是推测）：

1. 随机过程只读四五章就停，**这个停是对的**——考试范围既是边界，也是停止的合法性，也是终点和证据。
2. deeptutor 让人觉得重：功能越多，欠账越多；「精通之路」停在聊天框，因为它的步骤没有指向真实对象的落点。
3. 与 AI 讨论出来的创新，事后分不清哪一步是自己想的——**归因丢失**。

## 二、诊断：三个根因

| 根因 | 表现 | 现有实现对应 |
|---|---|---|
| **度量错位** | 产品度量输入（单元学完、覆盖率、生成稿） | `knowledge.json` 记每个知识点的掌握度、去重证据与到期；通关只看知识点 |
| **边界缺失** | 所有未读单元默认欠着 | 目标把资料裁成节级路线：必读 / 略读 / 不读，不读要写理由 |
| **归因缺失** | 分不清「我自己做到 / AI 给的」 | 只把模型判过或客观答对的作答当证据；自评保留但不计进度 |

一句话：**它是学习平台，而要解决的是「我能不能靠自己」这件事。**

## 三、核心回路（产品只有一个回路，五步）

1. **立目标**：交付物 + **期限（必填）** + 受众 + 选资料。禁止接受「我想深入理解 X」这种没有交付物的目标（或降级为「随手读」，不进账本）。
2. **定范围与标准**：
   - **节级路线**：从目标倒投影，得到三态「必读 / 略读 / 不读」（不读必须给理由）。
   - **概念级目标**：要读的节抽出 3–8 个知识点，每个点定一档：**了解 / 会用 / 能讲 / 创新**，对应掌握度阈值 0.6 / 0.75 / 0.85 / 0.95。
3. **读书做题**：读原文；过关测试只考目标内、还没到档位的知识点。作答由模型判定（客观题直接判），**写回知识点状态**：掌握度、去重证据、下次到期。
4. **复习**：按 FSRS 到期复习目标内知识点；时间流逝让掌握度衰减；同一道题重复作答只算复习，不再叠加证据。目标外的节或无目标时是**自由练习**：照样出题判分，但不写任何进度。
5. **结案**：所有目标知识点都到档位，且每个点的下次复习都落在期限规则之外（`max(30 天, 距期限 × 1.5)`）→ 归档，从此不再出现在「今天」。

**通过和评级分开**：通过只看「目标内知识点是否都到档位 + 模型结案研判」；题量、难度和证据数只影响下一次复习的间隔，不再当门槛。

**旧版兼容层**：判定题、独立尝试、归因三态、卡点、判定卡、按节 FSRS 仍在代码与旧数据里，但默认不进主回路；新目标不依赖它们。

## 四、核心对象

| 对象 | 内容 | 关键约束 |
|---|---|---|
| **Goal** | 交付物、期限、受众、资料、状态 | 期限必填；无交付物不许建 |
| **Route** | 每节的覆盖三态（必读/略读/不读）+ 理由 | 「不读」是一等公民，永不进未完成分母 |
| **KnowledgeTarget** | 知识点 + 档位（1–4）+ 所属节 | 只对目标内的知识点练习与复习 |
| **KnowledgeState** | 掌握度、峰值、去重证据、FSRS 到期、结案标记 | 唯一进度源；作答、复习、时间都写这里 |

**证据规则（防自欺的机关，别删）**：

- 模型判过或客观答对才算证据；自评不计进度。
- 同一道题按题干指纹只算一条证据，重复只按复习折扣计入。
- 一次答对不等于结案：要所有目标点都到档位，且复习排到期限之外。
- 结案后新证据可以让知识点重新打开。

## 五、判定标准：可判定性阶梯

| 层 | 例子 | 可否判定 | 谁负责 |
|---|---|---|---|
| 意图 | 深入理解强化学习 | 不可判定 | 不判定，只做翻译 |
| 交付 | 能独立推导这篇边缘计算论文的第 3–5 节 | 可判定 | 工具翻译成层三 |
| 证据 | 能白板推出 Eq.12；能解释此处为何用 TD 不用 MC | 可判定 | 用户执行 |

**模糊目标不是缺陷，是入口。** 工具的价值只在两个翻译动作：层一→层二（一次，几百 token），层二→层三（一次，可人工修正）。做完，那个大词就被替换成一张有小票的单子。

## 六、AI 的位置（三处，全部可选）

- **A 划边界与抽知识点**：把目录投影成必读/略读/不读；目标创建时给每节抽 3–8 个知识点并定档。一次性，最多覆盖 6 节，其余在第一次练习时补。
- **B 答疑**：卡住时问，答完即走，**不落库**、不进账本。
- **C 出题、判分与结案研判**：题目按目标与未达标知识点出；你写答案，模型只判你写下的东西。结案前模型再看一遍全部作答，确认「真的都过了」。**AI 不写掌握度数值**：它只给 pass/partial/fail，数值由确定性规则更新，保证同一份作答回放出同一个状态。

**红线**：AI 不进入「独立尝试进行中」；不预生成整节内容；没有 key 时仍可导入、读书、自由练习与自评（只是不记进度）。token 消耗被压到「一次划界 + 少量出题/判分」。

## 七、信息架构（两个入口 + 一个工具）

1. **书架**：书/论文的统一清单；导入、阅读、归档。
2. **阅读**：今日（当前目标 / 接着读 / 到期复习）、目标详情（路线、知识点档位、结案条件）。
3. **设置**：引擎、外观；不算一个学习入口。

「笔记（实验）」「自编书」「洞察」已从导航隐藏，不在主回路。

## 八、不做什么（红线清单）

1. 不做「替你读」的精读稿（导读）主流程；阅读面只出问题，不出答案。旧导读可保留为实验入口，默认隐藏。
2. 不做自编书、洞察卡、知识图谱可视化作为卖点；不默认生成。
3. 不做刷题系统、连续打卡、排行榜、成就；**不做组级评分当门槛**。
4. 不做覆盖率排名与「读完进度」叙事——分母只算必读集。
5. 不做云端账号与同步；数据是本地文件，随时可导出。
6. 不做移动端；不为窄屏妥协核心交互。
7. 不接受无交付物或无期限的目标（降级为随手读，不进账本）。
8. 不让 AI 参与独立尝试的进行中；不让 AI 直接写掌握度数值。
9. 不把「自由练习」的作答写进进度。
10. 阅读面不做任何形式的记账：不统计阅读时长、不记录已读段落、不显示块内计数、不做连续天数。进度只存在于知识点状态与目标完成度里。

## 九、阶段路线

- **阶段 0（已完成）**：文档定稿 + 文案/README 对齐。
- **阶段 1（已完成）**：原文面换成原文件 PDF；目标、裁剪单、判定题、归因与卡点、判定卡复习。
- **阶段 2（进行中，知识点空间 MVP）**：目标 = 节级路线 + 概念级四档 + 必填期限；练习/今日/复习按目标过滤；作答写 `knowledge.json`；结案由知识点达标 + 期限复习规则判定；自由练习不记进度。
- **阶段 3**：复习队列批量走完、目标创建时的概念质量与合并、旧数据迁移与旧功能删除；一个月后看指标再决定是否开源。

## 十、风险与失败模式

| 风险 | 触发条件 | 对策 |
|---|---|---|
| 退化回待办清单 | 目标写得太宽，边界划不出来 | 强制「交付物 + 期限」字段 |
| 概念空间碎成渣 | 同义概念不合并、id 随手起 | 概念抽取规范化；后续加合并/别名 |
| 假通过 | 只答对一两题就想结案 | 按档位阈值 + 到期复习规则；证据按题去重 |
| 归因记录变成负担 | 每次尝试要填太多 | 旧归因层冻结；主回路只要求作答 |
| 个人化太强，开源即被腐蚀 | 用户要求通用化 | 加功能先过第八节红线 |

## 十一、验收（自用一个月，可证伪）

- 30 天内至少完成 1 次目标结案；
- 结案时每个目标知识点都到档位，且复习排在期限之外；
- 同一道题重复作答不增加证据；
- 目标页到开始一次练习 ≤ 2 次点击；
- 无 AI key 时可导入、读书、自由练习；不会写假进度；
- 「生成整节内容」的调用 < 1 次/周。

## 十二、术语表（替换自造词）

变强清单 → **书架**；学习之路 → **阅读**；大道至简 → **笔记（实验）**；单元 → **节**；精读稿 → **导读（实验）**；洞察卡 → **笔记（实验）**；裁剪单 → **节级路线**；掌握点 → **知识点目标**；判定题 / 判定卡 / 归因 / 卡点 → **旧兼容层**（默认不进主回路）。

## 十三、这份文档怎么用

- 加功能前先读第八节；过不了红线就不做。
- 每次想改定位，先改这里，再改代码——顺序反过来就一定会漂。
- 任何实现，都必须能回答「它属于五步回路里的哪一步」；回答不上来的，就是在做可替代的那层。

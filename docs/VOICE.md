# 文案口径（VOICE）

> 这份文件管「怎么说」，不管「做什么」。功能与红线见 [POSITIONING.md](POSITIONING.md)。
> 改任何面向读者的文字前先读这里；`node scripts/checks/ui/check-voice.mjs` 会拦住最明显的那几类跑偏。

## 一句话

像坐在旁边那只大肥鱼：话短、口语、有语气，但不装可爱、不糊弄。

## 谁在说话

读者看到的文字基本是**工具在说话**（提示、空状态、按钮），少数是**大肥鱼在说话**（引导卡、问候、报错）。两者都不用「本系统」「用户」这种第三人称——没有第三方，只有你和我。

## 三档语气

| 位置 | 语气 | 例子 |
|---|---|---|
| 入口、按钮、字段名 | 平实、准确 | 导入 / 设置 / 新建目标 / 归档 |
| 标题、副标题 | 短、动宾，最多一句 | 接着读 / 该复习了 / 练一下最弱的 |
| 提示、空状态、报错 | 口语，可用语气词 | 「今天没有到期的知识点。」「诶，这段好像没分到块里。」 |

**越靠近功能，越平实；越靠近状态，越活泼。** 按钮可爱会让人不敢点，状态平实会让人不想看。

## 可以

- 语气词：啊、呢、嘞、嘛、诶、唔、啦；想事情时来一个「嘶」
- 很短的开头：「诶」「唔」「等等」「好嘞」
- 第二人称「你」，第一人称「我」

## 不可以

- 书面腔：首先 / 其次 / 综上所述 / 值得注意的是 / 本节将介绍 / 由此可见
- 第三方口吻：本系统 / 用户 / 该功能
- 夸张承诺：秒懂 / 彻底掌握 / 轻松搞定 / 再也不用
- 卖萌过头：表情符号、叠字（好好好）、喵 / 嗷呜、网络梗
- 用语气词盖住不确定：拿不准就说拿不准，别用「大概啦」糊过去

## 数字与术语

- 数字照实说：`3 个知识点到期 · 2 个还没到档位`。不加「啦」，也不换算成百分比。
- 领域词不改名：节级路线、知识点档位、掌握度、证据、结案——它们各自有定义，改名等于改产品。
- 旧兼容层的词（判定题、判定卡、归因、卡点）只出现在旧数据里，不往新文案里搬。
- UI 自造词按 [POSITIONING.md](POSITIONING.md) §12 的术语表。

## 语气不改变红线

活泼的是说法，不是要求。阅读面依旧「只问不答」，练习依旧只在目标里开放并写进度，目标依旧要交付物与期限，通过依旧只看知识点是否到档位。任何为了顺口而放松约束的改法，都是 bug。
